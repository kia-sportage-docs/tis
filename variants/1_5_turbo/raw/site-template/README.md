# TIS parts catalog prototype + local editor

Локальный каталог по OCR-артефактам из `../tables_md` и `../pages` с read-only просмотром и MVP-редактором схем.

## Что внутри
- `generate_catalog.py` — собирает базовый `data/catalog.json`.
- `server.py` — локальный HTTP/API сервер для UI и сохранения правок.
- `data/catalog.json` — исходный каталог, не меняется редактором.
- `data/overrides.json` — локальные ручные правки поверх каталога.
- `index.html`, `app.js`, `styles.css` — UI просмотра и редактирования.
- `assets/pages/` — локальные JPG схем.
- `serve.sh` — быстрый запуск локального сервера.

## Что умеет редактор
1. Включение `Edit mode` без ломки обычного просмотрщика.
2. Редактирование названия схемы.
3. Выбор кода детали для новой метки из:
   - уже существующих кодов на схеме,
   - списка `unmatched_codes`.
4. Добавление новой метки кликом по схеме.
5. Перетаскивание метки мышью.
6. Изменение размера метки за нижний правый маркер.
7. Точная правка `label`, `code`, `x`, `y`, `w`, `h` в боковой панели.
8. Удаление ошибочной метки.
9. Сохранение всех правок в `data/overrides.json`.
10. Автоприменение `overrides` при следующей загрузке сайта.

## Формат overrides
`data/overrides.json` хранит только ручные изменения, например:
```json
{
  "documents": {
    "DOC_ID": {
      "title": "Исправленное название",
      "markers": [
        {
          "editor_id": "manual-...",
          "code": "1125DA",
          "label": "1125DA",
          "match_method": "manual",
          "rect": { "x": 100, "y": 120, "w": 60, "h": 30 },
          "rows": [ ... ]
        }
      ]
    }
  }
}
```

## Как это работает
- UI загружает каталог через `GET /api/catalog`.
- Сервер читает `data/catalog.json` и накладывает поверх него `data/overrides.json`.
- По кнопке `Сохранить overrides` UI отправляет `POST /api/overrides`.
- Исходный `catalog.json` остаётся нетронутым, поэтому правки легко откатить удалением или редактированием `data/overrides.json`.

## Undo / Redo
- В редактор добавлены `Undo` и `Redo`.
- Они работают для ручных изменений в текущей сессии браузера: переименование схемы, добавление/удаление метки, перетаскивание, изменение размера и правка полей.
- История не заменяет сохранение: для фиксации результата всё равно нужно нажать `Сохранить overrides`.

## Как публиковать без возможности редактирования
Есть два практических варианта.

### Вариант 1: только просмотр как статический сайт
Опубликовать только:
- `index.html`
- `app.js`
- `styles.css`
- `data/catalog.json`
- `assets/pages/`

И не публиковать:
- `server.py`
- `data/overrides.json`

В таком режиме сайт останется просмотрщиком данных без сохранения правок.

### Вариант 2: отдельная publish-копия без UI редактора
Для финального read-only варианта лучше сделать отдельную копию сайта, где:
- скрыты или удалены `Edit mode`, `Undo`, `Redo`, `Сохранить overrides`
- загрузка идёт только из `data/catalog.json`
- нет API `/api/overrides`

Это самый чистый способ публикации для внешнего просмотра.

## Ограничения MVP
- пока нет zoom/pan-инструментов специально для редактора, только стандартный скролл браузера;
- история `Undo/Redo` работает в рамках текущей сессии редактора;
- список кодов для привязки берётся из текущего документа, а не глобально из всех документов;
- `unmatched_codes` не пересчитываются физически в файле overrides: редактор показывает их как список-кандидат для быстрого назначения;
- сохранение рассчитано на одиночное локальное использование.
