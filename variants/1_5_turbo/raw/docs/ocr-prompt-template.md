# Prompt для OCR TIS / каталога запчастей

Ниже шаблон промпта, который можно использовать для OCR страниц PDF/схем и вывода в нужный формат.

---

## Базовый prompt для одной страницы

```text
Ты обрабатываешь одну страницу каталога запчастей автомобиля.

Задача:
1. Определи тип страницы:
   - table
   - scheme
2. Если это table:
   - распознай таблицу максимально близко к исходнику;
   - выведи её в markdown;
   - сохрани структуру строк;
   - первый столбец считай идентификатором детали на схеме;
   - если один и тот же идентификатор встречается в нескольких строках, выведи все строки;
   - не объединяй разные строки;
   - не пересказывай, а именно распознавай.
3. Если это scheme:
   - извлеки короткое имя/идентификатор схемы;
   - если на странице есть только схема, без таблицы, таблицу не выдумывай.
4. Если текст читается плохо:
   - не фантазируй;
   - помечай сомнительные места как [неразборчиво].

Верни ответ строго в формате JSON:
{
  "page": <number>,
  "type": "table" | "scheme",
  "name": null | "...",
  "ocr_md": "..."
}

Правила:
- Для table: `name = null`, а `ocr_md` содержит markdown-таблицу или markdown-строки таблицы.
- Для scheme: `name` должно содержать имя/код схемы, а `ocr_md` может быть пустым или содержать краткую служебную подпись.
- Не добавляй пояснения вне JSON.
```

---

## Prompt для table-страницы

```text
Это страница таблицы каталога запчастей.

Распознай её в markdown.

Требования:
- сохранить строки как есть по смыслу;
- первый столбец — идентификатор детали;
- если у одного идентификатора несколько part-number, вывести все строки;
- не склеивать разные позиции;
- не переводить и не пересказывать;
- если часть строки не видна, пометить фрагмент как [неразборчиво].

Верни только markdown таблицы или markdown-строки таблицы, без пояснений.
```

---

## Prompt для scheme-страницы

```text
Это страница схемы каталога запчастей.

Нужно:
1. определить, что это именно scheme;
2. извлечь короткое имя схемы для имени файла;
3. если видны коды позиций, не расписывать всю схему текстом;
4. не выдумывать то, чего не видно.

Верни строго в формате JSON:
{
  "type": "scheme",
  "name": "...",
  "ocr_md": ""
}
```

---

## Prompt для поиска меток на схеме

```text
Это изображение схемы узла каталога запчастей.

Нужно найти на схеме текстовые идентификаторы деталей (коды позиций), например значения из первого столбца таблицы.

Правила:
- интересуют только коды/идентификаторы деталей;
- служебные подписи вроде FR., RR., LH, RH, FRONT, REAR — это не детали;
- не нужно пересказывать изображение;
- если код сомнительный, лучше пропустить, чем выдумать.

Верни список найденных кодов без комментариев.
```

## Prompt для итоговой chunk-структуры

```text
Ты обрабатываешь диапазон страниц каталога запчастей.

Для каждой страницы:
- определи type: table или scheme;
- для table распознай таблицу в markdown;
- для scheme извлеки name.

Итог верни строго в JSON-формате:
{
  "range": [<start>, <end>],
  "pages": [
    {
      "page": 1,
      "type": "table",
      "name": null,
      "ocr_md": "| ... |"
    },
    {
      "page": 2,
      "type": "scheme",
      "name": "21101",
      "ocr_md": ""
    }
  ]
}

Никакого текста вне JSON.
```

---

## Практическое правило для этого проекта

Для этого проекта использовать такую логику:
- table → распознавать в markdown;
- scheme → извлекать имя схемы;
- одна или несколько table-страниц перед scheme относятся к этой scheme;
- итоговый `.md` файл таблицы именовать по `scheme.name`.
